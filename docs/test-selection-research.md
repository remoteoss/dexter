# Test Selection Research Notes

## Status

This branch preserves an experimental function-level test-selection system. It
is research code, not a certified way to omit tests. The command must remain in
shadow mode until source, compiled, provider, and uncertainty evidence meet the
required correctness threshold.

Dexter selects and explains candidate test files. It does not run tests.

## Architecture

Dexter keeps one canonical live workspace database. The daemon owns it and
keeps source definitions, references, and source caller/callee edges current.

Compact SQLite snapshots are immutable revision artifacts. They exist because
impact analysis compares independent base and head revisions. They live in the
bounded impact cache or arrive as exact CI artifacts. No daemon owns or
incrementally updates them.

Compiled evidence is a delta over the source graph. It should add only evidence
that source parsing cannot represent:

- generated function identities and semantic fingerprints;
- calls generated by expanded macros or `use` output;
- finite inferred targets, with every possible target retained;
- callback and framework dispatch edges;
- compiled ExUnit ownership for generated tests and setup callbacks;
- opaque and unresolved evidence;
- module metadata, external resources, compiler configuration, and provenance.

Do not retain duplicate source and compiled call relationships under different
edge kinds. Keep evidence provenance separate from graph identity.

The repository owns compilation. Dexter does not invoke `mix`, `elixir`, or a
compiler. It consumes completed BEAMs, compiler-trace artifacts, and repository
provider artifacts. Missing, stale, or incomplete configured evidence widens
selection.

## Preserved Prototype

The branch contains:

- a persistent source caller/callee graph;
- deterministic forward and reverse graph traversal;
- callable source fingerprints;
- synthetic source test roots and ownership edges;
- immutable base and head impact snapshots;
- a direct compact snapshot writer;
- an impact-only parser and indexer path;
- native BEAM debug-information decoding;
- repository and provider evidence formats;
- conservative unresolved-evidence handling;
- daemon export for a clean exact `HEAD`;
- cache validation and bounded cache cleanup;
- a shadow-only `dexter impact` command.

## Performance Boundary

Compiled scanning and impact-only parsing must stay outside normal full builds,
incremental indexing, and LSP lookup paths. A clean-head snapshot should export
source evidence from the canonical database without reparsing source, then add
compiled deltas to the private snapshot under construction.

Traversal must use one shared multi-source state per graph. Do not use one
visited graph per changed function because memory then grows as changed
functions multiplied by reached nodes. Traversal limits must fail open to wider
selection and must never return a partial result as certified.

Before integration, measure these costs against the same fixed repository
revision:

- cold normal indexing time, CPU, peak RSS, database size, and WAL size;
- incremental save latency for call-dense files;
- parser allocations with and without call extraction;
- call graph table and index bytes through SQLite `dbstat`;
- narrow, typical, and wide SQLite traversals;
- direct historical snapshot construction;
- clean-head source export and compiled augmentation;
- artifact size, query count, rows read, and peak RSS.

## Correctness Gaps

Important gaps before certification include:

- macro-generated functions and calls;
- compiled ExUnit functions and setup callbacks;
- imported and `use`-injected callees;
- bare local calls without parentheses;
- literal and inferred `apply/3`;
- anonymous function invocation through captures;
- behaviour callback dispatch;
- Erlang atom modules;
- compiled-only dependencies;
- compile-time resources and configuration;
- generated code;
- repository-specific framework registries;
- arbitrary dynamic dispatch.

A resolved source symbol does not prove that every caller is represented.
Selection must stay in shadow mode until compiled evidence and uncertainty
handling cover these cases.

## Recommended Next Work

1. Remove duplicate source and compiled relations from snapshot construction.
2. Stream compiled deltas into clean-head export without source reparsing.
3. Validate exact compiled inventories and toolchain provenance.
4. Add generated test ownership and setup callback evidence.
5. Add callback and finite dynamic-dispatch evidence.
6. Compare candidates with an independent selector across representative exact
   revisions. Investigate every missing candidate and every full-suite fallback.
7. Keep selection shadow-only until all required evidence is present.

## CI Flow

The intended CI path is:

1. Download the exact base snapshot for the diff-base revision.
2. Run the repository's normal source and test compilation.
3. Export the clean head source graph from the canonical database, or build it
   once in an isolated CI process.
4. Add compiled deltas and repository evidence.
5. Analyze the independent base and head snapshots.
6. Let CI execute the returned candidate files.

Never substitute a newer default-branch artifact for the exact base revision.

parser, store, indexer, call graph, impact, daemon, and workspace packages.
